AUTHENTICATION, CREDENTIALS, AND SECRETS

This guide defines security rules, credential storage standards, and platform authentication specifications across our infrastructure tools.


1. SECURITY RULES

- Zero plaintext exposure: Never write passwords, tokens, or private keys to disk, command-line arguments, environment blocks, or chat responses.
- Memory decryption: Decrypt secrets in memory only when starting network sessions. Clear plaintext variables immediately after.
- Native DPAPI in Python: Use Win32 CryptUnprotectData with ctypes.windll.crypt32 directly in process memory. Do not start PowerShell child processes to decrypt secrets.
- Native DPAPI in PowerShell: Use [System.Security.Cryptography.ProtectedData] with CurrentUser scope.


2. CREDENTIAL STORAGE STANDARDS (CREDENTIALS.JSON)

Naming conventions:
- Single target workspace: credentials.json
- Multi-target environments: credentials.<target>.json (example: credentials.vcenter01.json)

Standard JSON schema:
{
  "target": "vcenter.corp.local",
  "username": "administrator@vsphere.local",
  "password_dpapi": "<base64-dpapi-ciphertext>",
  "token_dpapi": "",
  "updated_at": "2026-08-26T14:00:00Z"
}

Runtime rules:
- In-memory caching: Cache decrypted credentials in memory when iterating through multiple targets to avoid repeated DPAPI calls.
- Disable cookie containers: In PowerShell REST clients using HttpClient, set UseCookies = $false to prevent session conflicts between different credentials.


3. SETUP WORKFLOW AND MISSING CREDENTIAL HANDLING

Setup script requirements:
- Every workspace must include a Setup-Credentials.ps1 or setup_credentials.py script.
- Prompt for input with masked fields. Test the connection, encrypt secrets under CurrentUser scope, and write credentials.json.
- Silent test verification: Verify credentials with a test connection. Output only a pass or fail status. Never print, return, or log decrypted plaintext values.

Missing or invalid credentials rule:
- If credentials.json is missing or authentication fails, notify the user immediately.
- Output the exact command to run (such as .\scripts\Setup-Credentials.ps1 or python setup_credentials.py).
- Never ask the user to type passwords in chat.

Git and test isolation:
- The .gitignore file in every workspace must exclude credentials.json, credentials.*.json, and *.env files.
- Unit tests must never access production credential stores. Use mock objects or write test files to temporary directories.


4. PLATFORM AUTHENTICATION SPECIFICATIONS

VMware vSphere and vCenter:
- PowerCLI: Authenticate with a PSCredential object built from credentials.json.
- REST API: Call POST /api/session with Basic Auth. Use the vmware-api-session-id header on later requests.
- Local host accounts: Manage local ESXi accounts with HostLocalAccountManager and Get-EsxCli -V2. New-VMHostAccount fails through vCenter.

HPE iLO 5 and Redfish REST:
- Endpoint: Use HTTPS on port 443.
- Session creation: Call POST /redfish/v1/SessionService/Sessions. Save the X-Auth-Token header and Location URI.
- Session cleanup: Delete the session URI when the script stops.
- SSL: Disable urllib3 SSL warnings on internal self-signed addresses.

Nutanix Prism Central, Element, and CVMs:
- Prism REST: Use Basic Auth on port 9440. A 401 response confirms network connectivity and indicates an invalid password.
- CVM SSH/SCP: Use OpenSSH key authentication. Force legacy SCP mode with scp -O.

Graylog REST API:
- Headers: Use Basic Auth and the required header X-Requested-By: XMLHttpRequest.
- Search queries: Leave field wildcards unquoted in Lucene queries (source:app-*, not source:"app-*").

VMware Aria Operations (vROps):
- PowerCLI: Connect with Connect-OMServer.
- REST API: Get SessionSecret from the connection object. Pass it in Authorization: vRealizeOpsToken <token>.

OAuth2 / Cloud SSO:
- Grant type: Use client_credentials with POST .../token.oauth2.
- Headers: Use Authorization: Bearer <token>. Refresh tokens before they expire.
