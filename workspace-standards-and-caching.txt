WORKSPACE DIRECTORY LAYOUT AND TELEMETRY CACHING

This guide sets layout rules, execution standards, and data caching patterns across infrastructure workspaces under ~\code.


1. DIRECTORY LAYOUT

Every infrastructure workspace uses this directory structure:

<workspace-root>/
  Run-<Task>.ps1 (or main.py)          Master orchestrator script
  credentials.json                     Encrypted DPAPI credential file (gitignored)
  scripts/                             Numbered step scripts and setup utilities
    1_Fetch-<Telemetry>.ps1            Step 1: Collect live data
    2_Build-<Report>.ps1               Step 2: Aggregate metrics and build text report
    3_Build-HtmlReport.ps1             Step 3: Render standalone HTML
    Setup-Credentials.ps1              One-time credential setup script
  docs/                                Architecture references and session handoffs
  data/                                Hardware specs, IP lists, and baseline configs
  reports/                             Generated output reports and data cache
    <Report>.txt                       Current latest text report
    <Report>.html                      Standalone browser HTML report
    <Report>_YYYYMMDD.txt              Previous baseline report for comparison
    csv/                               Timestamped raw telemetry, summaries, and cache
    archive/                           Historical reports older than 30 days
  scratch/                             Temporary test scripts (must be gitignored)
  tests/                               Automated tests (mocked endpoints only)

Layout rules:
1. Put all executable automation scripts in scripts/. Every script must run independently.
2. Store raw telemetry, summaries, and 24-hour caches in reports/csv/ with ISO timestamps (YYYYMMDD).
3. Move historical reports older than 30 days into reports/archive/.
4. Place architecture notes and session handoffs in docs/ (such as docs/handoff-<name>.txt).
5. Put temporary test scripts in scratch/. Never leave scratch files in the root directory.


2. SCRIPT-FIRST EXECUTION AND AGENT TOOLING

Agent tool mandate:
- Always use built-in agent file tools (write_to_file, replace_file_content, view_file, list_dir) to create and edit files.
- Never write ad-hoc Python or shell scripts to manipulate workspace files.

Script-first rule:
- Never pass multi-line code to python -c or powershell -Command.
- Always write logic to a .py or .ps1 file in scripts/ or scratch/.
- Run scripts with uv run python scripts/<script>.py or pwsh -File scripts/<script>.ps1.

Python and uv package management:
- Never call bare python or pip directly.
- Initialize Python projects with pyproject.toml.
- Use uv sync to manage .venv dependencies locally on disk.

Step script execution model:
1. Numbered prefixes:
   Use 1_Fetch-..., 2_Build-..., 3_Render-... to make the pipeline clear.

2. Parameter parity:
   Every step script must accept common parameters (such as $OrgName, $Days, $ForceRefresh, $UseCache).

3. Standalone invocation:
   Test each script in isolation. Pass intermediate data through CSV files in reports/csv/.


3. LIVE INFRASTRUCTURE SAFETY RULES

Follow these safety steps before creating, modifying, rebooting, or deleting live resources:

1. Write the script to disk:
   Save the full script in scripts/ or scratch/ first. Test and inspect the logic.

2. Inform the user:
   List the target endpoints.
   Detail the exact changes.
   State if a host reboot will happen.
   Provide the rollback plan.

3. Get user approval:
   Wait for explicit user confirmation before running the script against live systems.

4. Dry-run support:
   Support -WhatIf in PowerShell scripts or --dry-run in Python scripts for modifying actions.


4. PROGRESSIVE DISCLOSURE IN SKILLS

Structure large skills with a references/ directory to minimize context pollution:

.agents/skills/<skill-name>/
  SKILL.md                  Main entry point and reference index
  references/               Specialized runbooks loaded on demand
    <topic-1>.md
    <topic-2>.md
  scripts/                  Standalone helper scripts

Skill design rules:
1. Keep SKILL.md under 40 lines with high-level instructions and a reference index.
2. Place detailed technical procedures into Markdown files in references/ (such as references/<topic>.md). Markdown supports links, headers, and code highlighting for agents.
3. Agents load reference files on demand only.


5. INFRASTRUCTURE DISCOVERY AND TELEMETRY CACHING

Network queries against large clusters are slow. Scripts use a 24-hour file cache to re-render reports quickly:

param(
    [string]$OrgName,
    [int]$Days = 90,
    [switch]$ForceRefresh,
    [switch]$UseCache
)

$SummaryCsvPath = "reports\csv\${OrgName}_Summary.csv"
$RawCsvPath     = "reports\csv\${OrgName}_Raw_${Days}d.csv"

# Check if cache exists and was modified within the last 24 hours
$isCacheValid = (Test-Path $SummaryCsvPath) -and 
                (Test-Path $RawCsvPath) -and 
                ((Get-Item $SummaryCsvPath).LastWriteTime -gt (Get-Date).AddHours(-24))

$shouldUseCache = $UseCache -or ($isCacheValid -and -not $ForceRefresh)

if ($shouldUseCache -and (Test-Path $SummaryCsvPath)) {
    Write-Host "Reading cached metrics from $SummaryCsvPath" -ForegroundColor Green
    $vmSummaries = Import-Csv $SummaryCsvPath
} else {
    Write-Host "Cache expired or ForceRefresh set. Calling live API..." -ForegroundColor Cyan
    # Read credentials.json as documented in authentication-and-secrets.txt
    # Run live queries here...
    $vmSummaries | Export-Csv -Path $SummaryCsvPath -NoTypeInformation
}
